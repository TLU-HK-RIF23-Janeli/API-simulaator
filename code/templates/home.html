TI API simulaator

Universaalne tehisintellektipõhine REST API mock server

Demorakendus API tööriist API dokumentatsioon

See simulaator loob TI abil realistlikke andmeid iga võimaliku ressursi jaoks ning simuleerib REST API-t. Esimene päring genereerib andmed, järgmised päringud tulevad andmebaasist, mis tagab stabiilse struktuuri. Lisaks on kasutajal võimalus päringuparameetriga kirjeldada soovitud andmestruktuuri.

Simuleeritud API toetab nii ressursside lugemist, loomist, muutmist kui ka kustutamist. Samuti on neid võimalik päringuparameetrite abil sorteerida.

Märkus: see tööriist töötab inglise keeles, seega API kirjeldus ja päringud peaksid olema inglise keeles, et TI saaks õigesti genereerida andmeid.

Kuidas see töötab?

1. API kirjeldus

Esmalt tuleb määrata API kirjeldus, mis defineerib, mis API-t rakendus simuleerib. Esialgu on API-l allpool toodud kirjeldus.

Kuidas?

Saada POST päring lõpp-punktile /specification või tee seda dokumentatsioonis. Seal on kirjas ka API spetsifikatsiooni kirjutamise põhimõtted.

{"specification":"You are an expert Mock API for Student Homework Management. Key domains: Users (Admin/Student), Assignments (Deadlines/Content), Tags (Academic Platforms), Comments, and Personal Task Statuses. Generate consistent, linked data suitable for testing a student-facing web application."}

2. Andmete pärimine

Päri soovitud andmeid kas läbi API tööriista, brauseri või oma frontend rakenduse. Esimesel päringul loob tehisintellekti mudel (OpenAI GPT 4o-mini) realistlikud andmed vastavalt API kirjeldusele, päringule ning soovitud andmestruktuurile, juhul kui see on päringuparameetrites kirjas.

Märkus

Eesrakendust arendades on ressursside soovitud väljad mõistlik kohe koodis defineerida, et vältida andmete struktuuri muutusi.

?schema=title,deadline,status Parameeter võimaldab tehisintellektile edastada täpse väljade nimekirja, mis ressursil olema peaks. Nii on võimalik tagada andmestruktuuri stabiilsus ka tühja andmebaasi puhul.

NB! Kui päring läheb TI-le, võtab andmete genereerimine mõne sekundi aega.

3. Andmete salvestamine

Esmakordse päringuga genereeritud andmed salvestatakse SQLite andmebaasi. Järgmised päringud samale lõpp-punktile tagastavad eelnevalt genereeritud andmeid, tagamaks andmestruktuuri stabiilsust ning andmete järjepidevust.

Märkus

Kui tahad tühja andmebaasiga uuesti alustada, siis DELETE /delete-all teeb andmebaasi tühjaks, samuti on vastav nupp olemas dokumentatsioonis.

4. API hetkeseisu näitamine

Oma simuleeritud API hetkeseisu näed dokumentatsioonis. Seal on olemas API spetsifikatsioon, loodud dünaamilised lõpp-punktid ning ka musta nimekirja kantud ressursid.

Peamised võimalused

Toetatud HTTP meetodid

  • GET — andmete lugemine (kogu kollektsioon või üks element)
  • POST — uue ressursi loomine
  • PATCH — olemasoleva ressursi muutmine
  • DELETE — ressursi kustutamine (eemaldatakse andmebaasist ning lisatakse musta nimekirja)

Päringuparameetrid

  • ?limit=10 — tagastab täpselt määratud arvu kirjeid
  • ?schema=title,deadline,status — sunnib AI-d kasutama täpselt neid välju
  • ?<any_other_param>=value — dünaamilised päringuparameetrid andmete sorteerimiseks ja filtreerimiseks
